# AgriSight QA Report — 26 Oct 2026

**Scope:** Full stack (Django 4.2 + Channels/uvicorn, PostGIS, Redis, React 18 + Vite) run from `main` (identical to your local copy apart from line endings), with Chrome (Playwright) testing of every public and protected route as an admin user and as a humanitarian user. The run used both an empty DB and a seeded DRC dataset (3 Kivu districts, stress events, conflict events, alerts).

**Automated checks:** backend tests 153/156 pass (3 errors). Vitest 9/9 pass. ESLint has 44 errors and 16 warnings. `vite build` passes.

## P0: blocks core use

| # | Issue | Evidence | Where |
|---|---|---|---|
| 1 | **The rate limiter logs users out within minutes.** The in-memory limiter allows 100 `/api/` calls per hour per IP. One dashboard load uses about 60 calls, because `/api/auth/user/` and `/api/auth/config/` are fetched on every route and every dashboard endpoint is fetched 6×. After the limit, `/api/auth/user/` returns 429 and AuthContext treats that as logged out, so the user is bounced to `/landing`. The limiter is also per-process (it differs per gunicorn worker), resets on restart, and can be bypassed with a spoofed `X-Forwarded-For`. | 68 × 429 on the 3rd page after login. Every protected page then redirected to `/landing`. | `backend/apps/core/middleware.py` `RateLimitMiddleware`; `frontend/src/contexts/AuthContext.jsx` |
| 2 | **Only the first sign-up ever works.** Allauth is configured username-less (`ACCOUNT_USER_MODEL_USERNAME_FIELD=None`), but `User.username` is still unique, so every user is saved with `username=''`. The 2nd registration fails with 500 `duplicate key ... (username)=()`. The raw DB error is returned to the browser, and the POST is retried 3× (see #6). | Reproduced: registering a second account returns 500. | `settings.py` allauth block, `authentication/serializers.py` `CustomRegisterSerializer.save` |
| 3 | **Map, Analytics, Exports and Conflict Reports crash to "Something went wrong".** These pages call `.map/.filter` on the regions response, but the response is a GeoJSON FeatureCollection (`results.features`). ISSUE-004 was fixed only in `Dashboard.jsx`. | `regions.map is not a function` in MapView.jsx:418, Analytics.jsx:629, Exports.jsx:38. `(… \|\| []).filter is not a function` in ReportGenerator.jsx:60. | Reuse `toFlatFeatureList()` in those pages, or add it in `lib/api.js` |
| 4 | **The Regions page says "No regions found" when regions exist.** It reads `data.results.length`, but `results` is a FeatureCollection object. Stress Events fails the same way (`results.map is not a function`). | 3 seeded regions; page shows the empty state. | `pages/Regions.jsx:73`, `pages/StressEvents.jsx:51` |
| 5 | **Geometry is returned as an EWKT string, not GeoJSON.** `"geometry":"SRID=4326;MULTIPOLYGON(...)"`. `rest_framework_gis` is missing from `INSTALLED_APPS`, so DRF never maps the geometry field. Leaflet will not be able to draw regions even after #3 is fixed. | `GET /api/v1/geospatial/regions/` | `settings.py` THIRD_PARTY_APPS |

## P2: robustness, DX, hygiene

- **Health check needs login.** `/api/health/` requires auth (403), but the frontend `healthCheck()` and docs use it. Only the middleware `/health/` is public. CLAUDE.md documents `/api/core/` but it is mounted at `/api/`.
- **Unknown URLs redirect to `/landing`** instead of the 404 page. Every anonymous page also logs 2 × 403 `/api/auth/user/` errors to the console.
- **The WebSocket URL fallback is inconsistent.** `apiClient` falls back to `localhost:8000` in dev, but `WebSocketContext` falls back to the page host (`ws://localhost:5173/ws/`). A fresh clone without `frontend/.env` (which is git-ignored) shows "Offline" and logs WS errors.
- **The dependency tree is inconsistent.** `pnpm-lock.yaml` was generated for React 19, but `package.json` says React 18 (so `--frozen-lockfile` fails). `react-leaflet@5` requires React 19 (unmet peer). An untracked `package-lock.json` sits next to the pnpm lock.
- **Backend packaging has latent breakage.** `djangorestframework-simplejwt==5.3.0` imports `pkg_resources`, which needs `setuptools<81` and isn't listed. `GDAL==3.7.2` is pinned while `python:3.11-slim` ships libgdal 3.6. The Dockerfile `CMD` still runs WSGI. The compose backend runs `makemigrations` on every start.
- **3 backend tests fail.** `reports_alerts.tests.DownloadReportRegressionTests` calls `create_user()` without `username`. This is the same bug fixed in ISSUE-001 for conflict_reports.
- **ESLint has 44 errors.** These include `rules-of-hooks` (conditional `useEffect` in `ErrorNotification.jsx:69`), `React` not imported in `lib/performanceMonitor.js` (its `useRenderTime` hook would throw), `process.env` in `ErrorBoundary.jsx`, and 25 unused vars.
- **React warnings:** `Button` is not wrapped in `forwardRef` (Radix `Slot` refs are dropped), and `<div>` is nested inside `<p>` on Alerts.
- **Production build has `minify: false`.** It is marked "debug build failure" in `vite.config.js`. Privacy, Terms and Support are placeholder pages.
- **Design-system drift:** the UI uses Inter and purple accents (`#8b5cf6`-style), which `DESIGN.md` forbids.

## Suggested fix order

1. #1 rate limiter: move it to Redis/django-ratelimit, scope it to auth endpoints, and stop treating 429 as logout. Also #2 username.
2. #3, #4 and #5: one shared GeoJSON normaliser plus `rest_framework_gis`.
3. #6 and #9: the apiClient retry and CSRF fixes.
4. #7 and #8, then remove the mock numbers (#10).

## How to reproduce locally

Run `agrisight/scripts/dev-local.ps1`. It starts the postgres, redis and backend containers, seeds QA users and data from `scripts/qa_seed_demo.py`, and runs Vite on http://localhost:5173. Log in as `admin@agrisight.test` / `AgriTest#2026` or `field@agrisight.test`.
